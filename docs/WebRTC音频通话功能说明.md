# WebRTC 音频通话功能说明

## 功能概述

在聊天页面中集成了基于WebRTC技术的实时音频通话功能，用户可以与在线好友进行语音通话。

## 主要功能

### 1. 发起通话
- 在聊天界面右上角点击"语音通话"按钮
- 只能向在线用户发起通话
- 系统会自动请求麦克风权限

### 2. 接听通话
- 收到来电时会弹出来电弹窗
- 显示来电用户头像和昵称
- 可以选择接听或拒绝

### 3. 通话控制
- **静音/取消静音**: 控制自己的麦克风开关
- **通话时长显示**: 实时显示通话持续时间
- **结束通话**: 主动结束当前通话

### 4. 通话状态
- 实时显示通话状态和时长
- 支持双方任意一方结束通话
- 通话异常时自动清理资源

## 技术实现

### 前端技术栈
- **WebRTC API**: 实现点对点音频传输
- **MediaDevices API**: 获取用户麦克风权限
- **WebSocket**: 信令服务器通信
- **Vue 3**: 响应式UI组件

### 后端技术栈
- **WebSocket服务器**: 处理信令转发
- **Spring Boot**: 后端框架
- **消息类型扩展**: 支持chat和webrtc两种消息类型

### WebRTC配置
```javascript
const rtcConfiguration = {
  iceServers: [
    { urls: 'stun:stun.l.google.com:19302' },
    { urls: 'stun:stun1.l.google.com:19302' }
  ]
}
```

## 信令流程

### 发起通话流程
1. 用户A点击"语音通话"按钮
2. 获取麦克风权限，创建RTCPeerConnection
3. 创建Offer并发送给用户B
4. 等待用户B的Answer

### 接听通话流程
1. 用户B收到call-offer信令
2. 显示来电弹窗
3. 用户B点击接听，获取麦克风权限
4. 创建Answer并发送给用户A
5. 建立P2P连接，开始通话

### 信令消息类型
- `call-offer`: 通话邀请
- `call-answer`: 通话应答
- `call-reject`: 拒绝通话
- `call-end`: 结束通话
- `ice-candidate`: ICE候选信息

## 使用注意事项

### 浏览器兼容性
- 需要现代浏览器支持WebRTC
- 建议使用Chrome、Firefox、Safari等主流浏览器
- 需要HTTPS环境（本地开发可使用localhost）

### 权限要求
- 首次使用需要授权麦克风权限
- 如果权限被拒绝，通话功能将无法使用

### 网络要求
- 需要稳定的网络连接
- 使用STUN服务器进行NAT穿透
- 复杂网络环境可能需要TURN服务器

### 性能优化
- 通话结束后自动清理音频流和连接
- 避免内存泄漏和资源占用
- 支持通话过程中的静音功能

## 扩展功能建议

1. **视频通话**: 扩展支持视频流传输
2. **群组通话**: 支持多人音频会议
3. **通话录音**: 添加通话录音功能
4. **通话质量**: 显示网络质量和音频质量指标
5. **TURN服务器**: 部署TURN服务器提高连接成功率

## 故障排除

### 常见问题
1. **无法发起通话**: 检查麦克风权限和网络连接
2. **听不到声音**: 检查浏览器音频设置和设备音量
3. **连接失败**: 检查网络环境和防火墙设置
4. **通话中断**: 检查网络稳定性

### 调试方法
- 打开浏览器开发者工具查看控制台日志
- 检查WebSocket连接状态
- 查看WebRTC连接统计信息
